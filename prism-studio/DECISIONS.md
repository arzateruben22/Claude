# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-10-24 | Next.js 16 (App Router, server actions, `proxy.ts`) + PostgreSQL + Drizzle; one worker process | One deployable app; Postgres gives row locks, `SKIP LOCKED` queues and unique-index idempotency |
| 2026-10-24 | Owner-only auth: a scrypt passphrase plus an HMAC session cookie (30 days) | One owner; no third-party auth needed for Stage A. The proxy checks every route, and each action checks again |
| 2026-10-24 | Manual publishing first, through the Upload Desk | Platform APIs need app review and verified accounts (Stage C); manual is safe and works today |
| 2026-10-24 | Approval = hash of the exact export plus the destination | "Approved" must describe exactly what will be posted, to exactly where |
| 2026-10-24 | One publication record per (episode, destination) | A YouTube upload must never mark TikTok or Instagram |
| 2026-10-24 | Achievements are unique per (rule, scope, demo) | Retries, re-imports and cross-posts can't unlock twice |
| 2026-10-24 | Rewards are reserved under a lock on the settings row, within the funded balance and monthly cap | Two workers can't spend the same money; nothing is reserved until the owner configures a cap |
| 2026-10-24 | Only API, CSV or owner-confirmed views count; a downward revision flags the evidence | Estimates and demo numbers must never unlock money |
| 2026-10-24 | Evolution needs real, reviewed work; the owner presses Evolve; the reveal plays once | Progress should feel earned, and never happen behind the owner's back |
| 2026-10-25 | Celebrations come from unseen achievements in the database, not from the form that caused them | The form may unmount in the same render (the task leaves the desk) |
| 2026-10-25 | Missed slots move to the next free day for that destination (never two a day) | No catch-up bursts |
| 2026-10-25 | Captions (.srt) come from the film's own word timings (film.json) | The burned-in captions and the uploaded captions match exactly |
| 2026-10-25 | Media is served only for allow-listed keys (`films:` inside `films/`, `media:` inside MEDIA_ROOT) | No path traversal; .env and source files are unreachable |
| 2026-10-25 | Default posting windows are provisional (YouTube 09:00, TikTok 12:00, Instagram 11:30/18:30, staggered 20 min per channel) | Not claimed to be optimal; analytics will decide |
| 2026-10-26 | Production budgets are monthly rows that carry forward until replaced; costs are recorded, never paid | One place to see spend against a plan; history stays correct when a budget changes. Prism never moves money, and the reward ledger is never touched |
| 2026-10-26 | Estimates and voided entries never count as spent; no currency conversion (other-currency costs keep paid generation off that month) | Only real, recorded spend uses budget room; Prism can't know an exchange rate, so it refuses to guess |
| 2026-10-26 | Paid generation needs the Settings switch, a channel budget with room, and room in the studio-wide budget when one is set | A studio-wide budget is a ceiling, never permission on its own |
| 2026-10-26 | "Show demo data" only changes what lists show; counting queries filter `is_demo` themselves | The switch can never make demo data count toward progress, rewards, XP, achievements or analytics totals |
| 2026-10-26 | API analytics: one `metric_snapshots` row per (post, metric, UTC day), upserted through a partial unique index; manual and CSV rows are untouched | Re-running a pull (retries, Refresh now, two workers) can never double a number; history keeps one point per day |
| 2026-10-26 | Pull cadence daily for 30 days after publication, then weekly, counted from the last attempt (`metric_pulls`), success or not | Numbers move fast early and slowly later; a failing post waits for its next period instead of looping |
| 2026-10-26 | An auth failure marks the connection expired, dead-letters that job, and stops all pulls from it until reconnected | One failed call, not a retry storm; the owner sees "needs reconnecting" on Analytics and Accounts |
| 2026-10-26 | Only a refresh the platform refused (auth, or a non-retryable rejection such as `invalid_grant`) marks a connection expired; a refresh that fails on the network or a rate limit leaves it connected and the queue retries. Instagram's insight refusals ((#10) too few viewers, the 200–299 permission family) fail that post's pull only | An expired connection also stops publishing; a passing outage or one low-reach post must not take an account offline until the owner reconnects |
| 2026-10-26 | Only verified publications are pulled (never simulated or demo); Stop external actions pauses pulls | Only a platform's own post id identifies the post; the stop switch means Prism doesn't call the platforms at all |
| 2026-10-26 | Push notifications with web-push (VAPID), the key pair made by the app on first need and stored in `push_keys`; the private key sealed with INTEGRATIONS_KEY, or with a key derived from SESSION_SECRET (HKDF, per purpose) when that isn't set, and moved under INTEGRATIONS_KEY once it is | No keys to generate or paste; never plain text, even on a dev box. Platform tokens still require INTEGRATIONS_KEY. If the sealing secret changes, Settings says so and offers a reset (devices turn notifications on again) |
| 2026-10-26 | Each notification is claimed by inserting its dedupe key (`push_events`, unique) before sending: at most once per event, even with two workers. When no device took it and one failed for a passing reason (5xx, timeout), the claim is released and the next tick inside the event's window tries again | A missed notification is better than a repeated one, and once any device has it, it isn't resent; but a push-service outage at the one moment an upload reminder fires shouldn't lose it |
| 2026-10-26 | Triggers: upload due 30 min before a manual slot with an approved, ready post (up to 15 min late if the worker was busy); a scheduled automatic publish that dead-lettered or ended handed off (inbox/private; not while still processing, not the owner's own Publish now); an Instagram slot passed with nothing planned (last 3 h). Never demo or simulated. Pause publishing silences upload-due and Instagram; Stop external actions silences upload-due | Notify only when the owner can act. Events are bounded by short lookbacks, so a newly added device doesn't get a backlog |
| 2026-10-26 | Push endpoints only on known browser push services (Google, Mozilla, Apple, Microsoft), over https; a 404/410 deletes the device, other failures are counted until the next success | The worker POSTs to the endpoint, so nothing else is reachable through it (no SSRF); dead browsers clean themselves up |
| 2026-10-26 | Written forms in written copy: only years after a year word (in, since, by, a month…), "X percent", and numbers of a hundred or more that read one way; everything else stays in words. A spoken pair ("nineteen twelve") becomes a year only before punctuation, a small word (the, we, when…), a name, or "and" plus another year | Narration is written for the ear; text is read. A wrong conversion ("at sixteen thirty" → 1630) is worse than none, so ambiguity leaves the words. Titles, sources and hashtags are the owner's or the researcher's and are never rewritten |
| 2026-10-26 | Sources that don't fit one comment become a thread (first comment + numbered replies), split only between sources; posting.json adds `replies` and keeps `pinnedComment` | Cutting sources hid citations behind "…"; a reply thread keeps every source within each platform's limit. A warning remains only when one source alone can't fit |
| 2026-10-26 | Sign-in throttle stays in the web process: per address 1/2/4/8 s backoff, then a 15 min lockout that doubles (to 24 h); at most 20 failures an hour studio-wide; one check at a time per address, every limit reserved before the check awaits | One web container, one owner: no table needed. The studio-wide ceiling covers spoofed or many addresses; reserving first means parallel requests can't overshoot. A restart forgets (only ever gentler); signed-in devices keep working during a lockout |
| 2026-10-26 | A device the owner signed in on keeps a signed `prism_device` cookie (400 days, separate from the 30-day session, never a session itself); with it, sign-in skips the studio-wide ceiling but not that address's backoff and lockouts | Strangers can fill the ceiling at will; without a way past it, the owner couldn't sign in on a phone whose session ran out. Restarting the container also clears it, but the attacker can start again at once |
| 2026-10-26 | After sign-in, `next` is parsed as a URL against the site and used only when it stays on it (and holds no whitespace, control character or backslash) | A regex on the first characters let `/<tab>/evil.example` through: browsers drop tabs and newlines and land on another host |
| 2026-10-26 | Settings: turning Paid generation on needs a channel budget this month; keeping it on doesn't (the gate refuses at run time), and a refused turn-on stays off with a notice while the rest saves | The switch must never block the same form's Stop external actions |
| 2026-10-26 | A same-day API re-pull that lowers a post's views marks the day's row revised and flags that post's unlocks, as a lower later row does | The row is updated in place, so comparing only with other rows missed the drop |
| 2026-10-26 | The throttle keys on the last `X-Forwarded-For` entry (Caddy sets it; Next fills it from the socket when there's no proxy) | The nearest proxy's view is the only one an attacker can't write; when it can be spoofed, the ceiling still holds |
| 2026-10-26 | Sign-in audit rows (`auth.sign_in`, `auth.sign_in_failed`, `auth.locked`, `auth.ceiling`) hold the address, counts and times, never the passphrase or its length; refused tries during a wait aren't logged | A record of who tried, without a log flood or anything that helps a guess |
| 2026-10-26 | Backups: a `postgres:16-alpine` sidecar running `deploy/backup.sh` (plain SQL, gzipped, verified, 14 daily + 8 weekly by hard link) into `./backups` on the host | Same pg_dump version as the server, no extra image to build, and files the owner can copy off with rsync; plain SQL restores anywhere with psql |
| 2026-10-26 | Restore loads into a new database and swaps it in by rename, keeping the replaced one; it refuses while the app or worker is connected | A bad or partial backup can't destroy the live database, and an undo is a rename |
| 2026-10-26 | Docker image: Next `output: "standalone"` plus only drizzle-orm, pg, web-push and tsx for the worker and scripts (pruned from the same lockfile install), no sharp (no `next/image`, `images.unoptimized`); a build-time esbuild resolve of the worker and scripts | 1.44 GB → 405 MB; the same package versions as development; a missing package fails the build, not the worker at night |
| 2026-10-26 | Home is a wall of monitors: the shared Instagram in the middle, one screen per channel around it, the channels with episodes nearest the centre; each opens a screen with every account's next post (`/m/<slug>`). Which channel sits where lives in one file (`src/lib/rig.ts`) | The owner posts account by account; one screen per channel puts each account's exact words, cover and buttons in one place. A phone shows the same screens as a stack, Instagram first |
| 2026-10-26 | Covers are one caption-free frame of the final (between two caption pages, away from the title card, the end card and cuts), drawn in the channel's own theme tokens and fonts. The import uses a cover only when it is newer than the render, else the film's poster. The cover is part of the approval hash | A cover must show this exact video, never an earlier render's. Burned-in captions in a cover read as a mistake. A new cover changes what is posted, so the approval ends |
| 2026-10-26 | Instagram rotation: two slots a day by default; channels take turns, starting after the last one placed on Instagram, oldest unplaced episode first; an episode goes on Instagram once, ever. A slot that passes with nothing planned reads "Missed" and spends no episode. The Instagram screen shows the order planning uses (it mirrors `planDays`) | One shared account carries five series, so no channel should crowd it; a repeat looks like a mistake to followers; a missed slot must not skip an episode silently |
| 2026-10-26 | Notifications go by web push to the owner's own devices (the installed PWA), not by email or SMS | No third-party account or cost, nothing to configure; on iPhone it works from the Home Screen app, and the phone is where the posting happens |
| 2026-10-26 | The sources comment and its replies are posted by the owner, by hand, even on connected accounts | Connectors upload the video, its text, the captions file and the thumbnail; they don't post comments. The desk gives the comment and each reply their own copy field, in order |
| 2026-10-26 | Hosting is one server running Docker Compose (Postgres, the web app, the worker, backups, Caddy), with the media on its disk, instead of managed Postgres and object storage | One owner and small files (a short is about 25 MB): one box is cheaper and simpler, and backups are plain files the owner can copy. Rendering stays on the films machine; finished files travel with `sync-media.sh`. Revisit if the disk fills or the studio must survive losing the server without a restore (there is no object-storage adapter yet; `.env.example` only reserves the `S3_*` names) |
| 2026-10-26 | Paid generation, per channel: the budgets are read in their own currencies first (no room, then the studio budget's room); then that channel's own actual costs in another currency hold it back, and, while a studio budget is set, any entry in another currency that month (studio-wide or any channel's), named with where it was recorded. Without a studio budget, a studio-wide or other channel's entry in another currency is listed as not converted and blocks no other channel | One €15 studio-wide entry turned every channel off with "another currency", even channels it had nothing to do with and channels already over budget. A cost in another currency can only use room up, so "no room" is the surer answer. But a studio budget covers every entry, so an unconverted one makes its room unknowable, and Prism never risks overspending (final check, 0.6.4) |
| 2026-10-26 | On /costs, "Studio-wide" means only entries with no channel; the unfiltered views are "All channels" / "All entries", and the ceiling is "the studio budget" | One word meant two things on one screen |
| 2026-10-26 | `npm start` runs Next's standalone server (`scripts/start.mjs`: copies `.next/static` and `public` beside `server.js`, reads `.env.local`, makes the media paths absolute), not `next start` | `output: "standalone"` stays for the Docker image, and `next start` doesn't support it; running the same server locally also catches a file the build didn't trace before it reaches the server |
| 2026-10-26 | Phones and touch screens: every link or button that stands on its own is at least 44 px tall; a route that sat inside a sentence becomes a button beside it. The More menu is opaque | Thumbs; desktop keeps its tighter rows. Inside the tab bar's backdrop-filter a translucent menu let the page show through far more than its alpha |
| 2026-10-26 | The preview is real screenshots of the production build on the dev database (`npm run preview`), replacing the static snapshot page (`scripts/snapshot.tsx`) | The snapshot drew the screens again in its own markup and fell behind the redesign. Screenshots of the real app can't drift; the server is started and stopped by the script |
